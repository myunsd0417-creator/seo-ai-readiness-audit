How to check Core Web Vitals for many pages at once

PageSpeed Insights is great for one page. But slow pages are rarely the home page. They are the product page with a huge image, the blog template with a heavy embed, or the landing page someone built last month. To find them, you need to test many pages, not one.

The three Core Web Vitals

MetricWhat it measuresGoodPoor
LCP (Largest Contentful Paint)How fast the main content appears2.5 s or lessover 4 s
INP (Interaction to Next Paint)How fast the page reacts to taps and clicks200 ms or lessover 500 ms
CLS (Cumulative Layout Shift)How much the layout jumps while loading0.1 or lessover 0.25

Field data vs. lab data

  • Field data comes from real Chrome users (the Chrome UX Report). It is what Google uses, but it needs enough traffic, so many pages have none.
  • Lab data comes from running Lighthouse in a controlled test. It works on any page, including new and low-traffic ones, and it tells you what to fix.

Lab tests cannot measure INP because nobody is tapping the page. Lighthouse reports Total Blocking Time (TBT) instead, which tracks the same problem: long JavaScript tasks that make the page slow to respond.

A simple bulk-testing routine

  1. Pick one URL per template: home, category, product or service page, blog post, landing page.
  2. Add your top 10 to 20 pages by traffic.
  3. Test on mobile first. Most problems show up there.
  4. Sort by LCP and fix the worst template first. One template fix often speeds up hundreds of pages.
  5. Re-test after each deploy that touches images, fonts, scripts or layout.

The usual fixes

  • Slow LCP: compress and resize the hero image, serve it in WebP or AVIF, and don't lazy-load the first image on the page.
  • High TBT / poor INP: remove unused scripts, delay chat widgets and trackers, and split large JavaScript bundles.
  • High CLS: set width and height on images and embeds, and reserve space for ads and banners.

Summary

  • Test one page per template plus your top pages, not just the home page.
  • Use lab data to find and fix problems. Use field data to confirm the result.
  • TBT in the lab points to the same issues as INP in the field.
  • Fix the worst template first.
