Did your pages turn noindex? How to check in two minutes

noindex tells search engines not to show a page in results. It is useful on purpose (thank-you pages, internal search results) and harmful by accident. When an important page turns noindex, it drops out of Google, and AI assistants that rely on search indexes stop finding it too.

The problem is that nothing looks broken. The page still opens normally in a browser. You only notice when traffic falls.

How pages turn noindex by accident

  • A staging setting goes live. Test sites are set to "hide from search engines", and the setting is copied to the real site during launch.
  • A CMS checkbox. WordPress has a "Discourage search engines from indexing this site" option. If it is ticked, the whole site is hidden.
  • An SEO plugin update or setting change marks a page type (categories, tags, products) as noindex.
  • A server or CDN rule adds an X-Robots-Tag: noindex header that you cannot see in the page itself.

The two places noindex hides

WhereWhat it looks likeHow to see it
In the page HTML<meta name="robots" content="noindex">View the page source and search for "noindex"
In the HTTP response headerX-Robots-Tag: noindexNot visible in the page. Use a header checker or the command below

Check your site in two minutes

  1. Open your most important page (home page, a top product or service page).
  2. View the page source and search for noindex. If you find it in a robots meta tag, the page is hidden.
  3. Check the header too. In a terminal: 
    curl -sI https://yourdomain.com/ | grep -i x-robots-tag
    No output means there is no X-Robots-Tag header.
  4. If you use Google Search Console, open the Pages report and look for pages listed as excluded by a noindex tag.
Do not block a page in robots.txt to "hide" it. If crawlers cannot fetch the page, they never see its noindex tag, and the URL can still show up in results. Use noindex alone for pages you want removed.

Summary

  • noindex can be in the page HTML or in the HTTP header. Check both.
  • Common causes: staging settings, a CMS checkbox, plugin changes and server rules.
  • Don't combine noindex with a robots.txt block on the same page.
  • A scheduled check catches it the week it happens, not months later.
